## 一、交付内容

### 1. 插件一键升级（架构 6.5.5 第 5 步）
| 组件 | 说明 |
|---|---|
| `installFromFile`/`installFromRelease` 加 `upgrade` 参数 | 升级模式跳过「已安装冲突」检查，直接走记录复用分支（Reinstall 更新版本 + activateInstalled 激活）；**升级前先 deactivate 停进程**（Windows 文件占用——替换目录前提） |
| `service.UpdatePlugin(ctx, instanceID)` | 停用 → 升级信息构建（市场清单 assets 声明优先，兜底默认 pattern `{id}-{version}-{os}-{arch}.bpk`）→ Release 下载安装（upgrade=true）；**失败时重新激活原版本**（解包校验失败不替换目录，原版本完好） |
| `service.CheckUpdates(ctx)` | 遍历已装进程外插件 → FetchLatestRelease → tag 去 v → `versionLess` 对比 → 可更新列表（无 Release/拉取失败跳过） |
| 接口 | `GET /admin/plugin-updates`（独立前缀避 Gin 参数段冲突）+ `POST /admin/plugins/:id/upgrade` + 上传 `?upgrade=1`（本地升级验证通道） |
| 前端 | 我的插件页：版本旁「可更新至 x.y.z」徽章 + 行内「升级」按钮（成功后刷新） |

### 2. iframe 短期 token（1 小时）
| 组件 | 说明 |
|---|---|
| `auth.Manager.GenerateShortToken` | 复用 sign（TokenType=access → **RequireAuth 中间件零改动**）；密码版本号传 0（受限场景令牌） |
| 接口 | `POST /api/v1/plugin-sandbox-token`（authed 组）→ {token, expires_in: 3600} |
| `sandbox.ts` | iframe load 后：已登录 → 请求 token → postMessage 下发 `{type:"init", user, token}`（插件凭 token 直接调用代理 API；匿名模式无 token；获取失败 postMessage 代理兜底） |

### 3. CSP 安全头（next.config headers）
- 全站：`default-src 'self'; script-src 'self' 'unsafe-inline' blob: [dev + 'unsafe-eval']; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self'; font-src 'self' data:; frame-src 'self'; connect-src 'self' ws://localhost:3000; object-src 'none'; base-uri 'self'; form-action 'self'` + X-Content-Type-Options/X-Frame-Options/Referrer-Policy
- **dev 模式追加 'unsafe-eval'**（Next webpack devtool source map 使用 eval）；**生产严格无 eval**
- **插件 ESM 加载适配**：发现 webpackIgnore 动态 import 走运行时 eval 被严格 CSP 拦截 → **loader 改为内联 `<script type="module">` 原生 ESM 桥接**（`import(blobUrl)` 原生执行，不触发 eval；并发加载按唯一 id 注册回调）

## 三、踩坑记录（新窗口防踩坑）

1. **升级替换目录前必须先停进程**：Windows 下运行中的 plugin.exe 占用文件 → RemoveAll 失败（4002 清理目录失败）——升级模式在解包后、替换前 deactivate。
2. **webpackIgnore 动态 import 触发 CSP eval**：webpack 运行时对非静态 import 用 eval 执行——严格 CSP（无 'unsafe-eval'）拦截。**解法**：内联 `<script type="module">` 内执行原生 `import(blobUrl)`（原生 ESM 不 eval），并发加载用唯一 id 注册全局回调。
3. **Next dev 模式自身用 eval**（webpack devtool source map）——CSP 需按环境区分（dev 加 'unsafe-eval'，生产严格）。
4. **.next 目录污染**：dev（next dev）与生产（next build/start）共用 .next 会互相损坏（prerender-manifest 缺失）——生产验证前必须 stop-all 干净构建。
5. **Gin 路由冲突**：`/plugins/updates` 与 `/plugins/:id` 参数段冲突——独立前缀 `/plugin-updates`（与 plugin-oauth 同思路）。
