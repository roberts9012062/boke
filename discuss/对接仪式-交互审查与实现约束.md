# 对接仪式 · 交互审查与实现约束

> 状态：评审意见稿（2026-09-06）。对象：博客后台「中继站」页的对接仪式交互（三态状态机 + 点火动画）。
> 结论：方向可行，与协议 v1.2 及 v1.5.5 已有实现兼容；**四条硬性约束必须先落实再动工**（§3），建议项见 §4。
> 实现归属：全部在 boke 仓库（`frontend/src/app/admin/relay/`），中继站零改动。

---

## 1. 原始设计摘要（站长口述，v2：免 key 申请流）

博客后台「中继站」页状态机：

- **未连接**：橙色星球与灰色卫星静态分立
- **申请对接**：只填中继站地址 → 点「📡 申请对接」→ 由**中继站审核分发对接认证**（key 不出现在任何输入框）
- **点火对接（全屏深空仪式）**：5-4-3-2-1 倒计时（大数字弹跳 + 青色进度环）→ 卫星从左侧机动飞向右侧星球（贝塞尔轨迹、抵达时火花脉冲、星球锁定缩放）→ "对接成功"（发光圆环 + 对勾描边动画）→ 点「进入大世界」自动正式启用
- **已对接**：状态卡显示"🛰️ 已对接"，可断开（许可保留，随时重新点火）

（v1 口述中"⚠ 通讯中断闪烁"归入已对接的故障子态，见 §3-1。）

## 2. 仪式术语与真实状态的映射（实现对齐表，协议 v1.3）

| 仪式术语 | 真实状态 / 接口 | 说明 |
|---|---|---|
| 申请对接 | `POST {relay}/api/v1/apply`（免 key，IP 限流） | 返回 apply_token 落库，状态进入「申请中」；同域待审不可重复申请 |
| 中继站审核分发认证 | 运营方后台批准 → 中继站建站 + 生成 key | 博客侧 `GET /apply/{token}` 每 30s 轮询 |
| 已获证 | 轮询命中 `approved`，**site_key 随响应自动写入 relay_config** | key 前端零暴露（无输入框、不回显）——"key 已隐藏保管"字面成立；meta/quota 随附用于回显中继站名称/规则/配额 |
| 点火对接 | `PUT /api/v1/admin/relay`（`enabled=true`）保存成功 | 动画是纯展示，见 §3-3 时序红线 |
| 进入大世界 | 跳转首页大世界 Tab / 关闭配置页 | 启用后订阅 worker 自动启动（watch ≤5s 生效） |
| 断开（许可保留） | `enabled=false` 保存，key 与配置保留，订阅 worker 停止 | 重新点火 = 重新启用 |

## 3. 硬性约束（实现前必须定稿）

### 3-1 状态机五态，断线警示归位

"⚠ 通讯中断"属于**已对接但中继站不可达**的故障子态，不能放在从未配置的空态里；免 key 申请流新增「申请中」等待态。定稿：

| 状态 | 判定 | UI 基调 | 可用操作 |
|---|---|---|---|
| ① 未连接 | 无配置（url 为空，无待审申请） | 引导空态：星球 + 卫星静态分立 + 欢迎文案，**无警示** | 填地址 → 申请对接 |
| ② 申请中 | 有 pending 申请（apply_token 在库） | 等待态："已向 中继站 发起申请，等待审核" + 申请时间 + 30s 轮询（页面停留期显示探测动画） | 撤回申请 / （rejected 时显示原因 + 重新申请） |
| ③ 已获许可 | key 在库、`enabled=false` | 中性展示：许可徽标 + 中继站名称/规则/配额回显（approved 响应随附） | 点火对接 / 断开 |
| ④ 已对接 | `enabled=true` | 状态卡"🛰️ 已对接" + 缓存计数 | 进入大世界 / 断开（带确认弹层） |
| ⑤ 已对接 · 通讯中断 | `enabled=true` 且最近一次握手/轮询失败 | **此态才显示**"⚠ 通讯中断"闪烁与重试说明 | 重试 / 查看日志 / 断开 |

状态来源：⑤ 依赖订阅 worker 的心跳结果暴露（需 boke 后端提供最近同步状态字段，如 `last_poll_ok` / `last_poll_at`）；② 的轮询由前端驱动（页面打开时轮询，审核结果落库后刷新状态机——审批通常发生在页面关闭期间，重进页面由后端查一次状态兜底）。

### 3-2 协议边界：申请是真实申请流，key 全程零暴露

「📡 申请对接」的实际行为 = 免 key 调 `POST /apply`（协议 v1.3 §4.11）：

- 博客侧 UI **不出现任何 key 输入框**；approved 后 key 由后端自动写入 relay_config，前端仅展示"对接认证已自动保管"；
- 申请被拒（`rejected`）时展示运营方填写的原因，允许重新申请；
- 同域待审不可重复申请（`APPLY_DUPLICATE`）、待审 7 天过期可重新发起——这两类提示要引导站长理解（"该域名已有待审申请，请等待审核"）；
- 中继站侧不回调博客（出站模式），一切凭 apply_token 轮询——内网/NAS 博客全流程兼容。

### 3-3 时序红线：状态以接口结果为准，动画只是庆祝

点「点火对接」：

1. **先发** `PUT /api/v1/admin/relay`（enabled=true）；
2. 请求成功 → 播全屏仪式 → 结束态"对接成功" + 「进入大世界」；
3. 请求失败（网络/校验）→ 不进仪式，直接行内报错，状态停在②。

禁止任何"动画播完即视为成功"的实现；仪式期间也不得重复发保存请求。

### 3-4 尊重「减少动效」全局设置

全局设置已开启「减少动效」的用户：跳过倒计时与飞行动画，仅静态呈现"对接成功"结果卡（或 ≤200ms 的淡入）。实现同样遵循 `prefers-reduced-motion`。

## 4. 建议项（不阻塞，实现时斟酌）

- **重复点火降噪**：断开后再次对接，默认静默重连（轻提示），全屏仪式仅首次对接播放；可留"重看仪式"彩蛋入口。
- **调性把握**：月言氛围是安静/夜色/慢节奏——倒计时与火花脉冲强度适度，若有音效默认静音。
- **双主题与移动端**：青色进度环、发光圆环过冷月（深）/薄雾（浅）双主题对比度；390px 布局验证。
- **图标体系**：📡🛰️⚠ emoji 与后台既有图标库的统一性；「断开」加确认弹层（断开后大世界内容立即消失，防误触）。
