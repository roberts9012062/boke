# 方案：书签批量清理「检测失效」条目

> 关联：`docs/browser-extension-guide.md` §8（代码规范）、书签模块（`sidepanel/components/bookmarks/`）。
> 状态：已评审通过，随插件 0.27.0 批次实现。

## 1. 背景与问题

书签页「🛠 管理 → 书签有效性检测」会把每个链接的可达性结果写进节点（`check.status: 'ok' | 'fail'`），列表中以绿点 / 红点标识。但检测出失效书签后：

- 现状只有单个红点提示，删除需进「编辑模式」逐个勾选再删除；
- 失效书签往往几十条（站点改版、文章下线），逐个删除体验很差。

## 2. 方案

提供**批量删除全部失效书签**的能力，两个入口汇合到同一个确认弹窗：

1. **管理菜单入口**：`🛠 ManageMenu` 新增「🧹 清理失效书签」项，实时显示失效数量（如「清理失效书签（12）」）；数量为 0（从未检测或全部有效）时置灰。
2. **检测完成快捷入口**：有效性检测完成的通知条上，若存在异常，直接追加「清理失效书签」操作按钮——检测完立即能一键进入清理，不用再打开菜单。

点击后弹出既有 `ConfirmSheet` 二次确认（展示将删除的条数、提示判定来自最近一次检测可能过期、不可恢复），确认后**一次剪枝**删除全部 `check.status === 'fail'` 的链接节点，通知条反馈删除数量。

## 3. 实现要点

| 点 | 说明 |
|---|---|
| `tools.ts` 新增 `collectDeadLinks` | 纯函数：收集全部 `check.status === 'fail'` 的链接节点 |
| `tools.ts` 新增 `removeIds` | 纯函数：按 ID 集合批量剪枝（不可变）；顺带收敛 `handleDeleteSelected` / `runDedupe` 中重复的内联剪枝逻辑（DRY），`removeNodeById` 委托实现 |
| `BookmarksTab.tsx` | `DialogKind` 增加 `'clean-dead'`；新增 `handleCleanDead`；通知条状态升级为 `{ text, action }` 结构，动作与文本同生命周期（避免按钮挂在无关通知上） |
| `BookmarkMenus.tsx` | `MenuItem` 支持 `disabled`；`ManageMenu` 增加 `onCleanDead` + `deadCount` |

## 4. 边界与取舍

- **判定快照**：失效判定来自最近一次检测，可能过期（站点可能已恢复），故必须二次确认并在文案中说明。
- **只删链接**：文件夹没有 `check` 字段，天然不受影响；空文件夹不因此清理（保持 YAGNI，不做级联空文件夹回收）。
- **不引入撤销**：与「查重清理」同水位，删除即生效（有双存储兜底但无版本历史），靠确认弹窗兜底误操作。

## 5. 验证

- `scripts/build-browser-extension.sh` 构建通过（TS 严格模式零报错）。
- Chrome / Edge 双浏览器按手册 §12 清单人工验证（检测 → 通知条一键清理 / 菜单入口清理 → 数量与列表一致性）。
