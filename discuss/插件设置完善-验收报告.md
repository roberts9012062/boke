# 插件设置功能完善（M3.7）验收报告

> 日期：2026-08-12
> 范围：插件设置端到端打通——SDK 契约 → 主进程运行时 → 存储接口 → 前端设置页 → demo 演示 → 冒烟

## 一、背景与缺口

原设置功能为「半成品」：设置页 UI 与 settings 表前缀键存储已有，但存在三个缺口：

| 缺口 | 影响 |
|------|------|
| ① schema 只认市场清单 | 本地安装插件（bpk 上传）设置页显示「插件不存在」，进不去 |
| ② 配置不下发到插件进程 | 配置只存主站 settings 表，插件是独立子进程读不到——「保存后即时生效」是空话 |
| ③ config JSONB 列闲置 | `plugin_instances.config` 列已建但全库无读写 |

## 二、设计

- **Schema 上报**：SDK 契约扩展——插件作者在 `Info()` 中声明设置项，`Info` RPC 上报；主进程聚合「进程上报优先、市场清单兜底」
- **配置存储**：统一到 `plugin_instances.config` JSONB（表已预留；不再污染全局 settings 表；开发环境无历史数据免迁移）
- **配置下发**：仿 LicenseProvider 的 `ConfigProvider` 回调 + 新 RPC `SetConfig`——Start 激活后下发（重启保持）+ 保存配置时 `PushConfig` 推送（即时生效）
- **SDK 侧读取**：仿 `sdk.License(ctx)` 包级内存模式——`sdk.SetConfig(values)` + `sdk.Config(ctx)`，插件 handler 内直接读取

## 五、插件作者使用方式（后期插件）

```go
// 1. 声明设置项（Info() 中）
func (p *MyPlugin) Info() sdk.Info {
    return sdk.Info{
        ID: "my-plugin", Name: "我的插件", Version: "1.0.0",
        Settings: []sdk.SettingField{
            {Key: "greeting", Label: "问候语", Type: "text", Default: "你好"},
            {Key: "enable_x", Label: "启用 X 功能", Type: "switch", Default: "on"},
            {Key: "theme", Label: "主题", Type: "select", Default: "auto",
             Options: []string{"auto", "light", "dark"}},
        },
    }
}

// 2. 钩子/API 中读取配置
func (p *MyPlugin) OnActivate(ctx context.Context) error {
    cfg := sdk.Config(ctx)
    log.Printf("greeting=%s", cfg["greeting"])
    return nil
}
```

后台「我的插件」→「打开设置」→ 保存 → **即时生效**（运行中进程收到推送）；重启/升级后配置保持（Start 激活时自动下发）。
