# 插件能力授权与数据服务（M3.8）验收报告

> 日期：2026-08-12
> 范围：插件开发手册 + 能力授权模型（capabilities）+ 只读数据服务（GRPCBroker）+ 钩子契约补全

## 一、需求来源

用户提出四关切：
1. **插件开发手册**——面向第三方插件作者的完整文档
2. **博客功能的授权**——插件能使用哪些博客能力的授权模型（此前 capabilities 仅展示、无校验）
3. **数据库访问**——插件对数据库的改变（此前插件无任何数据读取通道）
4. **增强/替换与解耦**——在原功能上新增/替换的扩展机制（此前钩子契约不完整、前端槽位仅追加）

## 二、设计

- **能力授权**：capabilities 枚举（hooks/api/frontend/settings 基础 + data.read 扩展）——安装校验（未知能力拒绝）+ 运行时门控（仅声明 data.read 的插件获得数据服务连接）
- **数据服务**：go-plugin v1.8 GRPCBroker（零配置即用）——主进程注册只读 DataService（GetUser/GetPost/GetSettings），Activate 时下发 brokerID；数据**只读 + 脱敏 + 白名单键**
- **数据库策略**：维持进程隔离——插件**禁止直连 DB**；读取走数据服务，变更走钩子/主进程 API
- **解耦**：DataProvider 接口注入（避免 plugin→repository 依赖）；契约统一 proto + buf 生成

## 五、排查记录（死锁修复）

初版 GRPCClient 中**同步调用 `broker.AcceptAndServe`**——其内部 `Accept(id)` 阻塞等待插件 Dial，而插件要等 Activate（在 Dispense 之后）才拿到 brokerID → **互相等待死锁**（后端启动卡死，Redis 挂时暴露：ping 重试 9 秒耗尽 ctx 余量后卡在 Dispense）。修复：**goroutine 异步 AcceptAndServe**。
