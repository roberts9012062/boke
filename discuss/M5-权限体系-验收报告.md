## 一、角色模型与权限矩阵（设计稿为准）

| 角色 | 权限范围（域） | 状态 |
|---|---|---|
| superadmin 超级管理员 | 全部 14 域（通配 *） | 启用（内置·不可删除·不可降级自己） |
| editor 编辑 | dashboard/posts/comments/media/tags/moderation/seo/ai/reports | 启用 |
| author 作者 | dashboard/posts（仅自己帖子）/media | 启用 |
| visitor 访客 | 无后台（前台阅读·评论，默认注册角色） | 启用 |
| restricted 受限访客 | 无后台 + 前台只读（发帖/评论/回复/私信发送 403） | 限制（设计稿状态列） |

- **迁移 011**：存量角色自动迁移 `admin→superadmin`、`user→visitor`（幂等 CASE；实测 1 superadmin + 5 visitor）
- **Casbin**：模型已支持 obj/act 细粒度（此前零调用）——本次落地 p 策略（`role, domain, "access"`）+ g 分组（用户名→角色全量）；`Enforce` 接入中间件
- **域清单 14 项**：dashboard/posts/comments/users/media/tags/settings/roles/moderation/plugins/seo/ai/reports/backups（域级粒度，域内读写细分后置）

## 二、后端实现

- **casbin.go 改造**：5 角色常量 + 14 域常量 + `defaultMatrix`（默认矩阵）+ `InitPolicies(custom)`（自定义矩阵覆盖，superadmin 强制全量）+ `SyncRoles` 全量加载（AllRoles 改全量查询）+ `SetRole` 白名单（先清旧分组）+ `Permissions`（按固定顺序输出）
- **中间件**：`RequirePermission(domain)`（Enforce 校验，替换原 RequireAdmin 硬编码）+ `RequireNotRestricted()`（前台写拦截）；路由重构为 14 个子组各挂域（约 50 端点）
- **author 数据隔离**：内容管理 5 接口（列表/详情/编辑/上下架/删除）author 仅限自己帖子（service 层校验 + 列表按作者过滤）
- **restricted 前台拦截**：发帖/编辑/发布/评论/回复/私信发送 6 个写接口 403「账号受限，仅可阅读」
- **角色矩阵接口**：GET /admin/roles（角色/人数/权限域/状态）+ PUT /admin/roles/:role/permissions（权限域编辑 → settings(role_permissions JSON) 持久化 + casbin 即时生效；superadmin 不可编辑）
- **角色调整升级**：PUT /admin/users/:id/role 五级白名单 + 自我保护（不可改自己）+ **审计写入**（audit_logs，action=set_role/update_role_permissions，before/after 快照 + IP/UA）
- 修复：SettingRepo 新增 `SetJSON`（SetMany 的 JSON 字符串包裹不适用含引号的 JSON 对象——role_permissions 专用）

## 五、过程问题

1. **SetMany 写入 JSON 对象失败**：settings 值的 JSON 字符串包裹逻辑（`"..."`）对含引号的 JSON 对象非法（22P02）→ 新增 SettingRepo.SetJSON 专用方法
2. **registerV1 作用域**：adminGroup 在 registerV1 内，enforcer 需穿过 Register → registerV1 两处签名
3. **buildHandlers 返回 enforcer**：Run 需 enforcer 构造路由 → 返回值扩展
4. **权限域顺序不稳定**：casbin GetFilteredPolicy 受 map 遍历影响 → Permissions 按 AllDomains 固定顺序输出
5. **前端 admin 硬编码残留**：me 页/用户主页/用户菜单 3 处 `role === "admin"`（TS 类型收紧后编译报错）→ 全部改 isSuperAdmin
6. **冒烟断言**：403 的 body code 是 1003（HTTP 状态才是 403）；登录限流 5 次/分（脚本加 62s 重试）；用户名带随机后缀（前缀匹配）

## 六、差异记录
