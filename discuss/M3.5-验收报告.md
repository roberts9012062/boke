## 一、交付内容

### 1. Ed25519 许可证体系
| 组件 | 说明 |
|---|---|
| `internal/plugin/license/` | 许可证核心包：`License` 结构（sub/licensee/edition/features/exp/signature）+ `Sign`/`Verify`（签名消息 = 去掉 signature 的规范化 JSON，签发验签同结构防字段漂移）+ `IsExpired`/`IsDegraded`（7 天宽限期）+ Ed25519 密钥对 PEM 读写（PKCS8/PKIX） |
| `cmd/license-issue` | 作者侧签发工具：`keygen`（生成密钥对）+ `sign`（签发 license.jwt，支持过期时间） |
| SDK 接口 | 契约新增 `LicenseInfo{edition, features, expires_at, degraded}`；`Activate` 签名从 Empty 改为携带 LicenseInfo（buf 重新生成桩代码）；插件侧 `sdk.License(ctx)`（只读快照）+ `FeatureEnabled(name)`（降级一律 false，demo 逻辑收敛于 SDK） |
| 主站验签 | `service/license.go`：`ActivateLicense`（验签 → 主体校验 sub=plugin:{id} 防跨插件复用 → 落库）+ `LicenseStatus`（demo/pro/degraded 状态）+ `LicenseInfoProvider`（进程激活时下发，manager LicenseProvider 回调装配，延迟绑定避免循环依赖） |
| pubkey 登记 | `installFromFile` 解包后读包内 pubkey.pem → `PluginRepo.SetPubkey`（plugin_instances.pubkey_pem 列已存在） |
| 降级机制 | 超宽限期（exp + 7 天）→ LicenseStatus degraded + 下发许可 features 清空 → 插件 FeatureEnabled 全 false；DB 状态保持 running（进程在跑，功能锁定） |
| 激活接口 | `POST /admin/plugins/:id/license`（:id 为实例 ID）→ 验签成功自动重启插件进程（SDK 许可缓存生效） |
| 迁移 013 | plugin_licenses 唯一索引（uq_plugin_licenses，支撑 ON CONFLICT 覆盖写入） |
| 错误码 | errs 新增 `4004 许可证无效/过期`（差异记录：架构 11.3 原 4003 语义已被 M3.4 解包错误占用） |

## 三、踩坑记录（新窗口防踩坑）

1. **签名消息重建**：Verify 必须先把 signature 存入变量再置空重建 message（否则解码的是空串，验签必败）；验签后恢复 Signature 字段（调用方可能读取）。
2. **类型与函数同名**：`sdk.License` 类型与 `License(ctx)` 函数冲突——类型改名 `LicenseInfo`，函数保持文档约定。
3. **:id 语义**：`/admin/plugins/:id/*` 的 :id 是**实例 ID**（int64），许可证激活/状态需先转 pluginID（新增 `PluginIDByInstance`）。
4. **宽限期语义**：exp 后 7 天内仍可用（不降级）——测降级需 exp 早于 8 天前。
5. **卸载保留许可证**：卸载（软删）不清 plugin_licenses（重装恢复授权）——冒烟需先清许可证记录再断言 demo 态。
6. **Gin 路由冲突**：`/plugins/oauth/*` 与 `/plugins/:id/*` 参数段冲突（panic）——OAuth 挂独立前缀 `/plugin-oauth/*`。
7. **许可证验证与断言**：demo 插件每次冒烟会积累 license 记录/进程/目录——步骤 1 需清实例 + 许可证 + 进程。
8. **环境故障排查**：全接口 6001 无 ERROR 日志时，先查基础设施（数据库/Redis 连通性）再查代码；登录耗时 2s+ 是 Redis 重试超时信号。
