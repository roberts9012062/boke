# M3.3 验收报告：插件进程外化（go-plugin + gRPC）

> 日期：2026-08-12
> 范围：M3 插件系统剩余核心——进程外插件（本次仅 M3.3，已与用户确认范围）

## 一、目标

把插件从「进程内钩子实现」升级为「独立子进程」（Hashicorp go-plugin + gRPC），
业务代码零侵入（Dispatcher 接口不变），以示例插件端到端验证完整链路。

## 二、交付内容

### 1. plugin-sdk（`pkg/plugin-sdk/`，monorepo 模式，本仓库内）
| 文件 | 说明 |
|---|---|
| `sdk.go` | 插件接口 `Plugin`（Info/OnActivate/OnDeactivate/Hooks）+ `Hook/Event/Result` + `APIMux`（自定义 API 注册，可选接口 `APIProvider`） |
| `server/serve.go` | 插件侧入口 `server.Serve(&Plugin{})`：go-plugin 握手（MagicCookie 与主进程一致）、gRPC 三服务注册、panic 恢复、API mux 分发 |
| `proto/plugin.proto` | 契约三服务（对齐架构文档 6.2）：PluginService（Info/Activate/Deactivate）/ HookService（Execute 同步钩子）/ PluginAPI（Call 自定义 API） |
| `proto/plugin.pb.go` + `plugin_grpc.pb.go` | buf 生成桩代码（**提交仓库**，第三方插件作者无需 protoc） |

### 2. 主进程侧（`internal/plugin/`，现有 4 文件 + 新增 4 文件）
| 文件 | 说明 |
|---|---|
| `manager.go` | 进程管理器：启用拉起子进程（AutoMTLS gRPC + 15s 握手超时）→ Info 一致性校验 → Activate → 注册钩子适配器；崩溃退避重启 1s→2s→…60s 上限、连续 5 次熔断（事件回调落库）；主进程退出时 Shutdown 全部子进程 |
| `binstore.go` | 插件二进制存储 `{dataDir}/plugins/{id}/plugin(.exe)`；插件 ID 白名单校验（防路径注入） |
| `grpc_bridge.go` | coreGRPCPlugin（client 侧）+ pluginClient 三服务客户端 + **钩子适配器**（Event JSON 序列化 → gRPC Execute → 响应还原，search.query 的 string Modify 兼容） |
| `proxy.go` | 插件自定义 API 代理（转发 PluginAPI.Call，10s 超时） |

### 3. 接线（业务零侵入）
- `internal/service/plugin.go`：Install（默认 installed → 激活成功转 running）、SetState（先激活/停用成功再落库）、Uninstall、SyncActivePlugins（重启恢复）
- `internal/service/plugin_runner.go`：activate/deactivate 统一入口（内置进程内 / 进程外拉起）+ PluginManagerEvents（崩溃熔断落库，独立类型避免装配循环）
- `internal/server/server.go`：装配 PluginManager（cleanup 先停插件子进程）
- `internal/router/router.go`：`/api/plugins/:id/*path` 代理路由（authed 组）
- `internal/handler/plugin.go`：Call 代理 handler（插件自定义格式透传）
- `internal/plugin/dispatcher.go`：新增 `RegisterWithID/UnregisterWithID`（进程外适配器是闭包，`%p` 函数指针比较会误判——按插件 ID 精确注册/注销）
- 前端：我的插件页展示 `crashed` 状态徽章 + `last_error`（含熔断后重新启用）

### 4. 示例插件与工具链
- `cmd/demo-plugin/`：进程外演示插件（post.before_publish 同步拦截 [demo] 标题 / post.after_publish 异步通知 / search.query 同步观察 / GET /ping 自定义 API）
- `scripts/setup-protoc.sh`：buf + protoc-gen-go 工具链安装（走 GOPROXY，无需下载 GitHub 二进制）
- `scripts/gen-proto.sh`：契约桩代码生成
- `scripts/build-demo-plugin.sh`：编译 demo 插件到 data/plugins/demo-plugin/
- `scripts/smoke_plugin.py`：全链路冒烟

## 四、踩坑记录（新窗口防踩坑）

1. **go-plugin v1.8 子进程日志双通道**：握手后插件进程的 `os.Stderr` 被 go-plugin **无条件替换为 stdio 流**（server.go `os.Stderr = stderr_w`），客户端经 `SyncStderr` 写入；**握手前**的输出走原始管道（`Stderr` 字段）。两者都要配置，否则激活后日志全丢：
   ```go
   ClientConfig{ Stderr: logFile, SyncStderr: logFile }
   ```
2. **go-plugin v1.8 API 变更**：无 `ExitChan()`（轮询 `Exited()`）、无 `ClientConfig.Timeout`（`StartTimeout`）、无 `Client.Cmd`（`Stderr` 字段）。
3. **崩溃计数语义**：Start 成功不能清零崩溃计数（否则「连续崩溃 5 次」永远达不到——每次重启成功都重置）；熔断后手动启用才重置。
4. **Registry 闭包处理器**：`sameHandler` 用 `%p`（code 指针）比较，同一工厂函数生成的闭包会误判相同 → 新增 `RegisterWithID/UnregisterWithID` 按插件 ID 精确匹配。
5. **binstore 路径**：`pluginDataRoot` 应为 `"plugins"`（相对 dataDir），误写 `"data/plugins"` 会拼成 `data/data/plugins`。
6. **Windows 冒烟**：PowerShell 输出 GBK，`subprocess.run(text=True)` 会 UnicodeDecodeError；用 bytes + `decode("gbk", errors="ignore")`；进程查找需 `Name -eq 'plugin.exe'` 排除 PowerShell 自身（命令行含匹配串）。
